# Repository Guidelines

## Project Structure & Module Organization

- `src/`: Application code.
  - `ui/`: React components and styles (`.jsx`, `css/`).
  - `nodes/`: Processing nodes (image, ml, comms, core).
  - `model/`: Graph, node, port, and library model classes.
  - `electron/`: Electron main process, preload, and IPC helpers.
- `examples/`: Sample projects for local/manual testing.
- `assets/`, `artwork/`, `res/`: App assets and build resources.
- `build/` and `dist/`: Build outputs (cleaned and regenerated by scripts).

## Build, Test, and Development Commands

- `npm install`: Install dependencies.
- `npm run format`: Format JS/JSX via Prettier.
- `npm run build`: Production build of the renderer (outputs to `build/`).
- `npm run build-library`: Rollup build of the standalone player (`figment-player.js`).
- `npm run fastdist`: Unsigned macOS app folder for quick local testing.
- `npm start`: Launch Electron in development mode.
- `npm run dist`, `dist-mac`, `dist-win`: Create signed installers for release.
- Note: Dist scripts clean `build/` and `dist/` automatically.

## Coding Style & Naming Conventions

- Language: Modern JS/React (ES modules).
- Formatting: Prettier with single quotes and 140 char width (`.prettierrc`).
- Indentation: 2 spaces. No semicolons unless required by tooling.
- Filenames: React components in `PascalCase.jsx` (e.g., `Editor.jsx`); nodes in `camelCase.js` (e.g., `reduceColor.js`).
- Components and classes: `PascalCase`; variables/functions: `camelCase`.
- Comments: write comments for expert coders to follow complex logic; avoid obvious comments. When making changes, update existing comments as needed, avoid adding comments like "ADDED THIS" or "FIXED THIS".

## Testing Guidelines

- No formal automated tests.
- Validate via `npm start`, open an `examples/` project, and exercise affected nodes/UI.
- For UI changes, verify on macOS and Windows if possible; include repro steps.

## Architecture Overview

- Core: `model/Network.js` orchestrates nodes; `model/Node.js` defines lifecycle (`onStart`, `onRender`, `onStop`); `model/DependencyGraph.js` handles execution order; `model/Library.js` loads node types from `src/nodes/` via JSDoc metadata.
- Nodes: live under `nodes/` (image, ml, comms, core). Typical header uses JSDoc (`@name`, `@description`, `@category`); define ports (`imageIn`, `imageOut`) and lifecycle hooks.
- Graphics: GPU image ops via WebGL/TWGL, shaders coordinated in `src/figment.js`.
- UI: React app in `src/ui/` (`App.jsx`, `Editor.jsx`, `Viewer.jsx`, `ParamsEditor.jsx`).
- File format: `.fgmt` JSON with nodes, connections, parameters; versioning in `src/file-format.js`.

## Commit & Pull Request Guidelines

- Commits: Imperative, concise, and scoped (e.g., "Add mirror option to webcam image").
- Branches: `feature/...`, `fix/...`, or relevant short scope (e.g., `codex/...`).
- PRs should include: clear description, linked issues, screenshots/GIFs for UI, steps to test, and platform notes if relevant.
- Keep PRs focused; avoid bundling unrelated refactors.

## Security & Configuration Tips

- Never commit secrets. Use `.env` and `.env.example` as references.
- macOS signing/notarization uses `electron-builder` config in `package.json` and `res/` entitlements; see `electron-builder.env(.example)` for local setup.

## Agent-Specific Instructions

- Safe in headless agents: `npm install`, `npm run format`, `npm run build`, `npm run build-library`, `npm run fastdist`.
- Local-only: `npm start` and `npm run dist*` (require Electron/runtime and codesigning access).
- Commit atomically: include only the changes you made so other agents' in-progress work stays isolated.
- Expressions: Nodes support JEXL expressions (`$FRAME`, `$TIME`, `$NOW`). MediaPipe models are cached in `assets/mediapipe*/`.

### Bundle Size Guardrails (ML deps)

- Bundle-size PRs may exclude `onnxruntime-web`, `@tensorflow/*`, and `@mediapipe/*` from `package.json > build.files`, but treat this as runtime-sensitive.
- If you change ML dependency packaging, also review `src/ui/index.jsx` and Vite asset behavior. Keep ORT `wasmPaths` overrides dev-only; production should resolve bundled asset URLs.
- After any changes in this area, validate both:
  - `npm start`: open a project and exercise ML-related flows/nodes.
  - `npm run fastdist`: launch the packaged app output and re-test the same ML flows.
- In packaged output, confirm required runtime assets are still present in `build/assets` and `build/mediapipe` (especially ORT wasm and MediaPipe task/wasm files).
- Do not assume `npm run build` success is enough for this class of changes; packaging can still remove files needed at runtime.
